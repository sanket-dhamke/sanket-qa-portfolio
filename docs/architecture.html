Hybrid router

A question hits a keyword/rule table. The first match wins. That is the whole router. There is no embedding index and no hosted model in this sample. If a model were plugged in later, it would only be allowed to rephrase text that a handler or the KB already produced — a model never produces a number.

1. Intent router Ordered keyword rules in agent/router.py. Vanilla JS port for GitHub Pages.
2. Handlers Read fixture JSON: cluster, metrics, ingestion sources, RCA. Return measured values only.
3. KB retrieval Score a local API catalog (~30 DataHub GraphQL/REST/recipe entries) and cite the file.
4. Fallback If nothing matches, a deterministic refusal. No invented CPU or asset totals.

Visible source field

Every answer carries source: handler:pod_status, handler:resource_metrics, handler:ingestion_assets, handler:ingest_recipe, kb:graphql.createIngestionSource, or fallback:deterministic. The console paints that chip next to the reply. pytest in tests/test_routing.py asserts the canned questions take different sources — no network.

DataHub vocabulary in this lab

Components: datahub-gms, datahub-mae-consumer, datahub-mce-consumer, datahub-frontend, datahub-actions. Ingestion uses recipe YAML (type: postgres / type: oracle), pipeline name, schema_pattern / table_pattern, sink datahub-rest to GMS. GraphQL: listIngestionSources, createIngestionSource (JSON-encoded recipe, executorId), createIngestionExecutionRequest. Aspects such as schemaMetadata and upstreamLineage show up in the fake run log. Public docs: Postgres source.

The in-browser console is a JS port of the Python router so GitHub Pages can run without a Python host. Python remains the source of truth.
